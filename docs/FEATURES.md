# MarkdownMate for Ubuntu features

Every feature of MarkdownMate for Ubuntu, with its menu item and shortcut. The [README](../README.md) has the short list.

Shortcuts use `Ctrl` where the macOS app uses `⌘`.

## Writing

- **Three view modes** (Ctrl+1 / Ctrl+2 / Ctrl+3): Edit, Preview, or side by side, where the preview and the editor scroll together, either way — scrolling the preview moves the editor's view, not its cursor (Preferences ▸ Sync Scrolling, on by default).
- **Syntax highlighting**: Markdown highlighting in the editor (can be turned off); by default Markdown is also styled inline — bigger headings, real bold/italic/code, dimmed markers.
- **Smart lists**: Enter continues lists, quotes and to-dos; Tab / Shift+Tab indents (4 or 2 spaces, set in Preferences).
- **Table editing**: in a GFM table, Tab / Shift+Tab move to the next / previous cell (past the last cell a new row is added), Enter adds a row below, and Enter on an empty last row leaves the table. Each step realigns the columns (accented and wide characters counted as they display, `:-:` / `--:` alignment kept); one Ctrl+Z undoes it. Tables inside `>` quotes or indented in a list item work too, keeping each row's prefix. Shift+Ctrl+T inserts an empty aligned 3-column table (header + 2 rows) at the cursor's line, with the cursor in the first header cell (not inside a code block); on a `>` quote or list line (the item line itself included), the table stays inside the quote / list item.
- **Table commands**: with the cursor in a table, Add Row Below (Alt+Ctrl+Enter), Add Row Above (Shift+Alt+Ctrl+Enter), Delete Row (Alt+Ctrl+Backspace), Add Column (after the cursor's), Delete Column (Shift+Alt+Ctrl+Backspace), Align Column Left / Center / Right (`:--` / `:-:` / `--:`) and Format Table (lines up the columns, keeping alignment and `\|`; a `|` inside a code span splits the cell, as in the preview — write `\|` to keep it in the code). They are in the main menu ▸ Table (with Insert Table) and on the table bar (or the format bar's table section). Each is one undo step, realigns the table and leaves the cursor in its cell; the header row can't be deleted, nor the only column.
- **Code block languages**: type ```` ``` ```` (or `~~~`) at the start of a line and a letter to pick the block's language from a list of the languages the preview colours (short names such as `js`, `ts`, `py`, `sh`, `yml`, plus `math` and `mermaid`): type to filter, Up/Down to choose, Enter or Tab to insert, Esc to close. Not offered on the fence that closes a block; ```` ``` ```` then Enter is still a plain new line.
- **Copy code from the preview**: hover a code block in the preview and click Copy (copies the code without the fences; not shown when printing or in Export/Copy as HTML).
- **Check off to-dos in the preview**: click a `- [ ]` checkbox in the preview to tick it in the note (Ctrl+Z undoes it).
- **Check off to-dos in the editor**: Toggle Task (Ctrl+Enter, or main menu ▸ Format) ticks or unticks the `- [ ]` / `- [x]` items on the cursor's line or the selected lines — all ticked if any was open, else all unticked. Other lines and code blocks are left alone; one Ctrl+Z undoes it.
- **Footnotes**: main menu ▸ Format ▸ Footnote inserts `[^n]` after the cursor or selection (the smallest number not used yet) and a `[^n]: ` line at the end of the note, with the cursor there to write the note; one undo. Not in code blocks.
- **Move Line Up / Down** (Alt+Ctrl+Up / Alt+Ctrl+Down, or Alt+Up / Alt+Down; main menu ▸ Edit): move the line with the cursor, or every line the selection touches, above or below its neighbour; the selection moves with it; one undo.
- **Duplicate Line** (Shift+Ctrl+D, main menu ▸ Edit): copy the line with the cursor, or every line the selection touches, just below; the selection moves to the copy; one undo.
- **Paste a link**: select text and paste a URL (http, https, mailto) to get `[text](url)`.
- **Paste formatted text**: text copied from a browser or LibreOffice pastes as Markdown (headings, bold/italic, links, nested lists, code, quotes, simple tables; web images as `![](url)`, not downloaded; scripts and styles dropped). Shift+Ctrl+V pastes plain text; inside a code block pasting is always plain. Spreadsheet cells that arrive as plain tab-separated text (a web spreadsheet, a terminal) with two or more rows and the same two or more columns on every row paste as an aligned Markdown table (first row as the header, `|` escaped); anything else pastes as it is.
- **Format keys**: Ctrl+B bold, Ctrl+I italic, Shift+Ctrl+H highlight (on the selection or the word at the cursor; press again to remove), Ctrl+K link (`[text](url)` with `url` selected to type over).
- **Wrap a selection**: select text and type `*`, `_`, `` ` ``, `~`, `[`, `(` or `"` to wrap it; the text stays selected, so `*` twice makes it bold.
- **Auto-pair brackets and quotes**: typing `(`, `[`, `{`, `` ` `` or `"` inserts matching pairs and places the cursor between them; typing the closing character steps over it, and Backspace inside an empty pair deletes both. Can be turned off in Preferences ▸ Editor.
- **Images**: paste or drop images (png, jpg, gif, webp, svg); they are saved to an `assets` folder next to the note, or the Attachments Folder of Preferences ▸ Notes (a name like `files` is next to the note; `/attachments` is a folder at the top of the open folder, as Obsidian vaults keep them; blank = `assets`) (pasted images as `image.png`, `image 2.png`, …; existing files are never overwritten) and linked as `![](assets/…)`. To keep screenshots small in synced folders, Preferences ▸ Notes ▸ Pasted Images saves pasted images as PNG or JPEG (quality 85, transparent areas on white; Keep Format, the default, saves them as PNG as before), and Scale Down To (Off, 1200, 1600 or 2000 px) shrinks wider ones to that width, keeping their proportions (a 3000 × 2000 screenshot at 1600 px becomes 1600 × 1067); smaller images are never enlarged. The file name follows the format (`image.jpg`). Both apply only to images pasted from the clipboard: image files you drop are copied as they are, and a pasted GIF or SVG is stored unchanged. Hover an image link in the editor to see a thumbnail (images in the open folder only; web images are never downloaded), Ctrl+click a link to open it. Obsidian's image sizes work in the preview, print and exports: `![Photo|300](a.png)` shows the image 300 pixels wide and `![Photo|300x200](a.png)` 300 × 200, with “Photo” as its alt text; other text after the last `|` (`![a|b](a.png)`) stays part of the alt text.
- **Drop files to link them**: drop other files or folders (from the sidebar or Files) into the editor to insert `[name](relative/path)` at the drop point, one link per line, the path relative to the note and percent-encoded (`a b.pdf` → `a%20b.pdf`); one Ctrl+Z removes them. Notes inside the open folder become `[[Name]]` instead (`[[Folder/Name]]` when another note has the same name, as Copy Wiki Link), so backlinks and rename updates follow them; notes outside it stay relative links. Dropped images are still copied to the attachments folder; dragging an entry from the sidebar into the editor links it and leaves it where it is. Links to notes open in the app; other files are not opened from a note.
- **Wiki links**: `[[Note]]` and `[[Note|shown text]]` link to another note in the open folder by name (case-insensitive, `.md` optional; `[[Folder/Note]]` to pick one — otherwise a note in the same folder wins, then the shortest path). Links to missing notes are shown in red. `[[Note#Heading]]` links to a heading of that note and `[[#Heading]]` to one in the same note. Ctrl+click in the editor or click in the preview to open it (at the heading, if one is named); clicking a link to a missing note creates it (empty, `Name.md` at the top of the open folder, or beside the note without a folder; `[[Folder/Name]]` only into an existing folder) and opens it. Typing `[[` pops up matching note names; typing `#` after the name (`[[Note#`, or `[[#` for the current note, which works without an open folder) pops up that note's headings — a heading whose title repeats is linked by its id (`setup-1`). Hover a wiki link in the editor to see the linked note's name and its first lines (up to 12 non-empty lines or about 600 characters, as plain Markdown, front matter left out) in a tooltip; `[[Note#Heading]]` shows the lines from that heading on. Links to missing notes and links in code show nothing. In Preview and Side by side, resting the pointer on a wiki link, an alias link, an embed's title or a link to a note (`[text](Note.md)`) for a moment shows the same preview at the pointer; it closes when the pointer leaves the link, on scroll, click or key press, and when the page updates. Links to missing notes and to a heading of the same note show nothing, and nothing shows while the Find in Preview field has the keyboard. A note can go by other names: list them under `aliases:` (or `alias:`) in its YAML front matter — `aliases: [Meeting notes, MN]`, a block list of `- MN` lines, or `aliases: Meeting notes, MN` (split at commas only; quotes optional) — and `[[MN]]`, `[[meeting notes#Agenda]]` or `[[MN|text]]` lead to it everywhere a wiki link works: preview, Ctrl+click, the tooltip, Backlinks and the exports. A note actually named `MN` wins over the alias; two notes with one alias follow the same-name rule. `[[` completion lists matching aliases after the note names as `MN → Note`, inserting `[[MN]]`. Renaming the note leaves `[[alias]]` links as they are. Aliases are reread when a note's front matter changes on disk (after saving).
- **Block references** (Obsidian-style): end a paragraph, a list item, a quote or a table's last row with a space and `^id` (letters, digits and `-`), or put `^id` alone on the line right below it, to name that block. As Obsidian writes it, `^id` alone after one blank line names the paragraph, list, quote, code block or table above (after two blank lines it stays text). The marker stays in the editor, dimmed, and is left out of the preview, print, exports, Copy as HTML / Rich Text and plain text, where the block gets the id `^id`. `[[Note#^id]]`, `[[Note#^id|text]]` and `[[#^id]]` (this note) link to the block: Ctrl+click or a click in the preview opens the note at the block's first line, and the hover tooltip shows the note from there. Hover previews leave the `^id` markers out. `[[Note#^` completion lists the note's block ids (after its headings for `[[Note#`). A list item's id covers its nested items; a quote's goes on its last line. Ids in headings, code, formulas and front matter are text; when an id appears twice, the first block has it. Find Broken Links lists `Note#^id — no such block` when the note has no such id. **Copy Link to Block** (editor right-click menu, or main menu ▸ Edit) copies `[[Note#^id]]` for the paragraph, list item, quote or table at the cursor: a block without an id first gets a new one (` ^` + 6 random letters and digits not used in the note) at the end of its last line, or for a table alone after one blank line below it, as one undo step; a block with an id keeps its text. The note name is written as `[[` completion writes it (`Folder/Note` when two notes share the name); with no folder open or an unsaved note it copies `[[#^id]]`. It is greyed out on a heading (use the Outline's Copy Link to Heading), in code, front matter or a footnote, and on a blank line.
- **Embeds** (Obsidian-style, with a folder open): `![[photo.png]]` shows an image of the folder (`.png`, `.jpg`, `.jpeg`, `.gif`, `.webp`, `.svg`, `.bmp`, `.tiff`, `.heic`, any case), found by name like a wiki link — the nearest one, or `![[Folder/photo.png]]` to pick it; `![[photo.png|300]]` sets its width in pixels and `![[photo.png|300x200]]` width and height. `![[Note]]` shows that note inside this one, in a framed block headed by its name (click the name to open it), front matter left out; `![[Note#Heading]]` shows only that heading's section, down to the next heading of the same or a higher level, and `![[Note#^id]]` only that block (a paragraph, a list item with its nested items, a quote or a table; see Block references). Embeds go one level deep: an embed inside an embedded note, or a note embedding itself, shows as a plain link; images inside an embedded note load relative to that note. A missing image or note shows the text `![[…]]` dimmed; `![[Note|text]]` ignores the text. Embeds in code are left as written, and without an open folder they stay text. Edits to an embedded note show the next time the preview renders the whole note (switching notes or reopening it). Print, PDF / HTML export, Copy as HTML / Rich Text and Export Folder as HTML show embeds the same way. `[[` completion and the hover tooltip work after `![[`; hovering an image embed shows its thumbnail and Ctrl+click opens it. Find Broken Links lists embeds whose image or note is missing, Find Unused Attachments counts `![[x.png]]` as a use, and Backlinks lists notes that embed the current one.
- **Tags**: `#tag` or nested `#work/project` anywhere in a note (starting with a letter, so `#1` is not a tag; not in headings' `#`, code, or URLs/links); colored in the editor and shown as chips in the preview. Tags in the YAML front matter count too (not colored): `tags: [work, ideas/books]`, a block list of `- work` lines, or `tags: work, ideas` (also `tag:`; a leading `#` is optional; values that are not valid tags are skipped). The sidebar's Tags section lists them as an indented tree (by `/`) with the number of notes; a note tagged `#work/project` also counts for `#work`. Click a tag to list its notes, then click one to open it. Ctrl+click a `#tag` in the editor (the pointer turns into a hand) or click its chip in the preview to jump there: the sidebar opens with that tag selected and its notes listed (only with a folder open; front-matter tags are not clickable). Right-click a tag ▸ Rename Tag… to rename it in every note of the folder: `#work` becomes `#job` and nested tags move with it (`#work/project` → `#job/project`), matching any case, in the front matter too (`tags: [work]` → `tags: [job]`, other keys untouched); `#older`, tags in code, URLs and links are left alone. You see how many notes change before anything is written; the open note changes in the editor (Ctrl+Z undoes it), and a note edited elsewhere meanwhile is skipped. Renaming to a tag that already exists merges the two. The list updates in the background when notes change on disk (after saving). Typing `#` and a letter pops up the folder's existing tags that match (by prefix, or letters in order), most-used first: Up/Down to choose, Enter or Tab to insert, Esc to close (not in code or headings' `#`). The files stay plain Markdown.
- **Format bar** (Shift+Ctrl+M, or main menu ▸ Format ▸ Format Bar; off by default, remembered): a bar above the editor with buttons for Heading (each click goes one level further, `#` … `######`, then back to plain text), Bold, Italic, Strikethrough, Highlight, Inline Code, Link, Bulleted / Numbered / Task List, Quote, Code Block and Insert Table. Bold, Italic, Highlight and Link do what Ctrl+B / Ctrl+I / Shift+Ctrl+H / Ctrl+K do; Strikethrough, Highlight and Inline Code wrap the selection or the word at the cursor in `~~` / `==` / `` ` `` (again to remove). The line buttons work on the cursor's line or every line the selection touches and toggle: all lines get the prefix (numbers count up), or lose it if they all had it; list kinds replace each other, a quote goes around a list; on a blank line they start one; code blocks are left alone. Code Block fences the lines with ```` ``` ````, or removes the fences of the block the cursor is in. While the cursor is in a table, the table bar's buttons show at the end of the format bar. Each button is one undo step and leaves the cursor in the editor; hover one for its name and shortcut. Hidden in Preview.
- **Table bar**: while the cursor is in a table and the format bar is off, a bar under the editor shows the table commands — Row: Above / Below / Delete, Column: Add / Delete, the three column alignments and Format (hover a button for its full name and shortcut); it hides again outside tables.
- **Wrap lines & line numbers**: toggle in Preferences (Ctrl+,) ▸ Editor; lines wrap by default, line numbers are off.
- **Typewriter scrolling** (Preferences ▸ Editor, off by default): the cursor's line stays in the middle of the editor as you type, move with the arrow keys or click (not while dragging a selection), with room below the text so the last line can reach the middle too.
- **Spell check** (Preferences ▸ Editor ▸ Check Spelling; on by default, remembered): misspelled words are underlined as you type. Right-click one for suggestions, Add to Dictionary or Ignore; the same menu has Check Spelling (the same switch) and Languages (for the open window only). The language is your system's, or US English if no dictionary covers it (add one with `sudo apt install hunspell-<code>`, e.g. `hunspell-fr`). Inline code, ```` ``` ```` code blocks and link URLs are skipped; `~~~` code blocks and code indented by 4 spaces are checked like text (GtkSourceView's Markdown rules). A note is checked from the top down in the background without slowing typing: a typical note in a few seconds, about 3 minutes per MB. Notes over 1 MB are not checked, so a huge note never keeps the check busy for minutes: the status bar says *Spell check is off for notes over 1 MB*, and right-click ▸ Check Spelling checks that note anyway (until you open another one; `docs/PERFORMANCE.md`).
- **Focus Mode** (Shift+Ctrl+J, or main menu ▸ Focus Mode; off by default, remembered): the editor dims every paragraph except the one you are writing in. A paragraph is a block of lines between blank lines (so a table or a code block without blank lines is one), and in a list each item is its own paragraph; on a blank line every paragraph is dimmed (the cursor's line stays bright), and with a selection the paragraphs it touches stay bright. Dimmed text keeps its colours (headings, links, code), faded, in every theme, light or dark; find highlights, spelling underlines and images on dimmed lines fade with it; works with typewriter scrolling. Only the editor's display changes: the note, the preview, print and exports are untouched.
- **Line spacing & text width** (Preferences ▸ Editor): Line Spacing 1, 1.15, 1.3, 1.5 or 2 (1 by default); Text Width Narrow (680 px), Medium (820 px), Wide (1080 px) or Full Width (Medium by default) keeps long lines readable on wide screens: the editor's text is centred at most that wide, and so is the preview's page; Full Width has no limit in either, so the text fills the window edge to edge (the side padding stays). Print and exports are unchanged.
- **Go to Line** (Ctrl+L): jump to a line, or `line:column` (1-based; past the end goes to the last line / line end).
- **Find & Replace** (Ctrl+F / Ctrl+H): a bar above the editor. Ctrl+F searches as you type (case-insensitive, also for Vietnamese and other accented text; a selection on one line becomes the search text), highlights every match and selects the next one after the cursor; `N of M` shows where you are (`No results` in red). A match inside a closed callout opens that callout. Enter or Ctrl+G goes to the next match, Shift+Enter or Shift+Ctrl+G to the previous one, wrapping around. Ctrl+H adds the Replace row: Replace (Enter in the Replace box) replaces the current match and moves on, Replace All (Ctrl+Enter) replaces every match in one step that a single Ctrl+Z undoes. Esc closes the bar and returns to the editor. From Preview, Ctrl+H switches to the editor first. Changes are saved by auto-save like any edit.
- **Find in Preview** (Ctrl+F in Preview, or in Side by side with the preview focused): a find bar above the rendered note. It searches as you type (case-insensitive), highlights every match and shows how many there are (`No results` in red); A match inside a closed callout opens that callout. Enter or Ctrl+G goes to the next match, Shift+Enter or Shift+Ctrl+G to the previous one, wrapping around. Esc closes the bar and clears the highlights. There is no Replace here: edit in the editor.
- **Status bar** under the editor: `Ln X, Col Y · N words · M characters` (counts the selection when there is one; Markdown markers are not counted as words).
- **Themes**: Default, Paper, Graphite and Solarized, each in Light and Dark (following the Style setting), for the editor and the preview; pick one in Preferences ▸ Appearance. Print and Export as HTML always use Default light.

## Preview

- **Rich rendering**: GitHub-flavored Markdown with code highlighting and footnotes — fully offline. Hover a footnote reference in the preview and, after a moment, the footnote's text appears in a small box beside it (long footnotes scroll), so you can read it without jumping to the end of the note; a click still jumps there. YAML front matter (`---` on the first line, as in Obsidian/Jekyll/Hugo) shows in the preview as a small properties table: one row per key, lists such as `tags: [a, b]` joined as “a, b”, nested values as YAML in one cell, everything else as written. Front matter the table can't read shows as the dimmed block it was. Preferences ▸ Preview ▸ Front Matter switches between *Table* (default), *Source* (the block as written) and *Hidden*; Export Folder as HTML follows it, while Export, Copy as HTML and Print leave front matter out.
- **Web images** (Preferences ▸ Privacy ▸ Load Images from the Web, off by default): with it off nothing leaves your computer — `http(s)` images are not downloaded in Preview, Side by side, Print or Export, the preview shows their alt text and a line saying why. Turn it on to show them there as in the macOS app; only images load from the web, never scripts, styles or anything else. An exported HTML file always lets the browser that opens it load them.
- **Line breaks** (Preferences ▸ Preview ▸ Line Breaks): *Markdown Standard* (default) joins lines of a paragraph as Markdown does; *Every New Line* shows each newline as a line break, as in the macOS app — in Preview, Side by side, Print, Export as PDF / HTML and Copy as HTML / Rich Text. Plain-text and RTF exports and the editor are unchanged.
- **Smart punctuation** (Preferences ▸ Preview ▸ Smart Punctuation, off by default): straight quotes become “curly quotes” and ‘apostrophes’ (it’s), `--` an en dash (–), `---` an em dash (—) and `...` an ellipsis (…) in Preview, Side by side, Print, Export as PDF / HTML / RTF, Export Folder as HTML and Copy as HTML / Rich Text. A quote opens at the start of a paragraph and after a space, `(`, `[`, `{` or a dash, and closes everywhere else. Code, math, raw HTML, front matter, links' addresses, URLs, tags and backslash-escaped characters (`\"`) stay as written, and so do heading anchors. Your note, the editor and the plain-text export keep the text exactly as you typed it.
- **Mermaid diagrams**: a ```` ```mermaid ```` code block shows as a diagram (flowcharts, sequence, class, state, Gantt, pie, …) in Preview and Side by side, in the light or dark colours of the current style. A diagram with a mistake stays a code block with a short error line under it. While you type, only the diagram you edit is drawn again. Mermaid is bundled (no network) and loaded only for notes that have a diagram, so other notes open as fast as before. Print and Export as PDF / HTML show the diagrams too (exported as plain SVG); Copy as HTML keeps them as code.
- **Math**: `$…$` (inline), `$$…$$` and ```` ```math ```` blocks (display) are typeset by KaTeX in Preview and Side by side — fractions, matrices, `\begin{aligned}`, most LaTeX math macros — in the text colour of the current style, light or dark. A formula with a mistake shows its source in red; hover it for KaTeX's message. While you type, only the formula you edit is typeset again. KaTeX and its fonts are bundled (no network) and loaded only for notes that have a formula. Print and Export as PDF / HTML typeset them too (the exported file embeds KaTeX's styles and fonts, no script); Copy as HTML gives MathML, which mail and office apps can paste. `$5 and $10` stays text.
- **Alerts and callouts**: a quote whose first line is `[!KIND]` (any case) shows as a coloured callout with its title — GitHub's `[!NOTE]`, `[!TIP]`, `[!IMPORTANT]`, `[!WARNING]`, `[!CAUTION]` (blue, green, purple, amber, red) and Obsidian's kinds: abstract / summary / tldr, info, todo (teal), hint, success / check / done (green), question / help / faq (orange), attention (amber), failure / fail / missing, danger / error, bug (red), example (purple), quote / cite (grey) — in light and dark, in Preview, Side by side, Print, Export as PDF / HTML and Copy as HTML / Rich Text. Text after the kind (`> [!tip] Keep it short`) replaces the default title; a fold marker makes it fold, as in Obsidian: `> [!info]- Title` starts closed, `> [!info]+ Title` open, and clicking the title opens or closes it — in Preview, Side by side, Print, Export as PDF / HTML, Copy as HTML and Export Folder as HTML (Export as RTF, Copy as Rich Text and the plain-text export show it open). An unknown kind such as `[!FOO]` and a marker in code stay as written. Export as RTF shows it as an indented quote under a bold title in the kind's colour; Copy as Rich Text keeps the coloured border and title. The plain-text export keeps the quote with its `[!NOTE]` line. Main menu ▸ Format ▸ Callout inserts any of these kinds: on a blank line it adds `> [!kind]` and `> `, on a line with text it adds them above the paragraph (followed by a blank line), with a selection the selected lines become the callout's body (quoted lines get one more level); one undo step, not in code blocks or front matter.
- **Comments**: `%%text%%` on a line, or lines between two lines that are only `%%`, are left out of the preview, print and every export except plain text; the editor keeps them. Not inside code, front matter or math; an unclosed `%%` stays as written.
- **Highlights**: `==text==` shows with a soft yellow background in the preview (light and dark, every theme), print, HTML / PDF export and Copy as HTML (`<mark>`); Copy as Rich Text and Export as RTF give it a yellow background, plain text keeps the `==`. The editor shows it on a light background with dimmed `==`. Format ▸ Highlight (Shift+Ctrl+H, or `==` on the format bar) wraps the selection or the word at the cursor, and removes the `==` when applied again; one undo step. As with `~~`, a `==` next to a space (`a == b`, `== text==`), `===`, a pair split over two lines, and `==` in code, links' URLs or front matter stay as written.
- **Table of contents**: a paragraph that is only `[TOC]` (any case) shows the note's headings as a nested list of links that jump to each heading — every heading before and after it, `#` to `######`, not those in code or front matter — and follows your edits as you type. Preview, Side by side, Print, Export as PDF / HTML and Copy as HTML; Copy as Rich Text and the plain-text and RTF exports keep `[TOC]` as written. `[TOC] text`, `[TOC]` in a quote, a list or code stay as written; no headings, nothing shows.
- **Links between notes**: click (in the preview) or Ctrl+click (in the editor; the pointer becomes a hand over links) a relative link to another note (`[Plan](Projects/Plan.md)`, `../Other%20Note.md`; with a `#heading` anchor such as `Plan.md#next-steps` it opens scrolled to that heading, the editor's cursor on its line) to open it; only existing Markdown files inside the open folder are opened (no `..` or symlink escapes). Web links (`http`, `https`, `mailto`, also bare URLs and `<…>` in the editor) open in the default app; other schemes are ignored. Ctrl+click on an image link in the editor opens the image in the default app if it is inside the open folder. Links in code are not clickable.
- **Keeps up with large files**: while you type, the preview updates in place and only the code blocks you changed are highlighted again; a note's code blocks are highlighted on all CPU cores at once. Backlinks of a note in a folder of 10,000 notes list in about 0.3 s. Timings for 1 MB and 5 MB notes and a 10,000-note folder: [`docs/PERFORMANCE.md`](docs/PERFORMANCE.md).

## Folders & navigation

- **Folder sidebar**: open a folder (Open… takes a file or a folder; recent folders are listed; Files ▸ Open With ▸ MarkdownMate), create, rename, delete (to the Trash), and drag a note or folder onto a folder (or empty space = the open folder) to move it, never overwriting. Renaming or moving a note or folder in the sidebar asks whether to update the links to it in the folder's notes — wiki links, relative `.md` links and images, not in code — and a moved note's own relative links (Don’t Update is the default; renames in Files change nothing). Drop `.md` notes from Files or the desktop onto the sidebar to copy them in the same way (a taken name gets a number, e.g. `Note 2.md`; other files are skipped); follows changes on disk. Right-click a folder ▸ Find in “Name”… to search only its notes (see Find in Folder). Right-click an entry for Show in Files (opens Files with it selected), Copy Path (its full path on the clipboard) and Move to Folder… (pick the folder from a list of the open folder's folders instead of dragging; it moves and offers the same link updates as a drag, and the sidebar then shows it); on a note, Copy Wiki Link copies `[[Name]]` ready to paste, or `[[Folder/Name]]` when another note in the folder has the same name. Duplicate copies a note or folder (with everything in it) next to itself as `Name copy.md` / `Name copy` (`Name copy 2.md` when taken); the sidebar shows the copy and a note copy opens. Bookmark folders and switch between them (Alt+1…Alt+9).
- **Select several sidebar items**: Ctrl-click adds or removes a note or folder, Shift-click and Shift+↑ / Shift+↓ select a run of them; a plain click still opens a note, and selecting never changes the note shown. Right-click one of the selected items for the actions that apply to all of them — Duplicate, Add to / Remove from Favorites (notes only; Add when some are not favourites yet), Show in Files, Copy Path (one path per line), Move to Trash (asks once, naming how many; Delete does the same) and Move to Folder… (one list, one question about updating links); an item inside a selected folder goes with its folder. Drag the selection onto a folder to move it all (one link question), or into a note to insert one `[[link]]` per note, each on its own line. Moved items stay selected at their new place, and the selection survives the sidebar refreshing from disk.
- **Favorites**: right-click a note or folder ▸ Add to Favorites to pin it in a Favorites section at the top of the sidebar (shown once it has an entry), in the order added; Remove from Favorites in the same menu, or on the Favorites row, takes it out. Click a favourite note to open it, a favourite folder to show it in the tree. Each folder you open has its own Favorites, remembered across restarts. They follow a rename, a drag or Move to Folder… done in the app and leave with Move to Trash; one removed or renamed outside the app shows dimmed and is removed when you click it. Sort Sidebar By leaves their order alone.
- **Sort the sidebar** (main menu ▸ Sort Sidebar By, or Sort By in an entry's right-click menu): by Name, Date Modified or Date Created, one setting for every folder, remembered. Folders always come first, by name; names sort naturally (`Note 2` before `Note 10`, case and accents ignored); dates are newest first, so today's notes are on top, and a note you save (or another app changes) moves up right away without closing any folder. Date Created is the file's creation time where the file system records it (ext4, Btrfs), else its modification time; saving replaces the file (the safe way MarkdownMate and most editors write), so on Linux a note saved here counts as newly created.
- **Bookmarks** (bookmark button in the header bar): bookmark the open folder (Bookmark This Folder / Remove Bookmark) and pick a bookmark from the list to open it; Alt+1…Alt+9 open the first nine. A bookmarked folder that no longer exists is skipped with a message. Below the bookmarks, **Recent** lists the last 10 folders you opened (newest first, the open one left out); click one to open it. A recent folder that no longer exists is removed from the list with a message.
- **Outline** (Alt+Ctrl+O or the list button in the header bar): a side panel with the headings of the current note (`#`…`######` and underlined `===` / `---`, not those in code blocks), indented by level and updated as you type; click a heading or press Enter on it to jump to its line in the editor. Right-click (or long-press) a heading → **Copy Link to Heading** copies `[[Note#Heading]]` to the clipboard, ready to paste into another note; **Rename Heading…** changes its text (level and closing `#`s kept, one undo step) and updates every wiki link to it across the folder — `[[Note#Heading]]`, `[[Note#Heading|text]]`, `![[Note#Heading]]`, `[[Folder/Note#Heading]]`, `[[Alias#Heading]]` and `[[#Heading]]` in the note itself. The dialog says how many links in how many notes will follow. Links follow only to the first heading with that text, as clicking them does; code, front matter and Markdown links (`[t](Note.md#slug)`) are left as written. The heading of the section the cursor is in stays highlighted as you move around, without taking focus from the editor.
- **Backlinks**: under the outline, the notes that link to the current note — by `[[Note]]` / `[[Note|text]]` / `[[Note#heading]]` (same matching as the preview, aliases included) or a relative Markdown link such as `[text](../Note.md)`; links inside code are ignored. Each entry shows the note name and the linking line; click it (or press Enter) to open that note at that line. Refreshed when you switch notes, after the folder is rescanned and when a note changes on disk; "No backlinks" when none. The links of every note are read once in the background when the folder opens and kept up to date, so the list appears at once even in large folders.
- **Unlinked Mentions**: below Backlinks, a collapsed section listing the notes that name the current note without linking to it — its file name or one of its aliases as a whole word, in any case (the first one in each note), not inside code or an existing link or wiki link (names shorter than 3 characters are not looked for). It searches only while expanded, in the background, so large folders stay responsive. Each entry shows the note name and the line; click it (or press Enter) to open that note at that line. Refreshed like Backlinks. The **Link** button on an entry turns that mention into a wiki link to the current note, at once: `[[Name]]` (`[[Folder/Name]]` when another note has the same name, as Copy Wiki Link) when it matches the name apart from case and accents, else `[[Name|mention as written]]`. If the note changed since the list was made and the mention is no longer where it was found, nothing is written and a message says so; the list then updates.
- **Today's Note** (Ctrl+D, or main menu ▸ Today's Note): opens `YYYY-MM-DD.md` for today's date in the daily notes folder of the open folder (Preferences ▸ Notes ▸ Daily Notes Folder, `Daily` by default, a path relative to the open folder; empty = the open folder itself). The first time each day it creates the note (and its subfolders), starting from a `Template.md` at the top of that folder (with the placeholders of New from Template below: `{{date}}`, `{{time}}`, `{{title}}` — here the file name without `.md` — and `{{cursor}}`, including formatted dates such as `{{date:dddd, MMMM D, YYYY}}` → Sunday, November 1, 2026), or `# ` + the file name and a blank line if missing or unreadable, and opens with the cursor at the template's `{{cursor}}`, or at the end; after that it just opens it. Unavailable until a folder is open.
- **Open Today's Note at Launch** (Preferences ▸ Notes, off by default): when MarkdownMate starts and reopens your last folder, it opens Today's Note as Ctrl+D does. Not when it starts with a file, a `markdownmate://` link or `--today`.
- **Daily note name** (Preferences ▸ Notes ▸ Daily Note Name, `YYYY-MM-DD` by default): how daily notes are named, so MarkdownMate finds the ones an existing vault already has. Use the date tokens of `{{date:FORMAT}}` — `YYYY` `YY` `MMMM` `MMM` `MM` `M` `DD` `D` `dddd` `ddd` — with other text in `[brackets]` and `/` for subfolders of the daily notes folder: `YYYY/MM/YYYY-MM-DD` keeps 2 November 2026 in `Daily/2026/11/2026-11-02.md`, `YYYY-MM-DD dddd` names it `2026-11-02 Monday.md`, `[Journal] YYYY-MM-DD` `Journal 2026-11-02.md`. The name needs a year, a month and a day; time tokens, other letters outside brackets (such as `WW`), a leading `/`, `..` or an empty folder name are refused, with the reason under the field, and the last valid name stays in use. Today's Note, Daily Note for Date…, Previous / Next Daily Note and Open Today's Note at Launch all follow it: a note counts as a daily note when its path inside the daily notes folder matches the name for a real date (letter case and a mismatching weekday name are ignored), so other notes there are left alone.
- **Daily Note for Date…** (main menu, after Next Daily Note): a calendar on today, with the days that have a daily note marked. A line below says what Open does: "Opens 2026-11-02.md", "Creates 2026-11-02.md from Template.md" (the path inside the daily notes folder, so `2026/11/2026-11-02.md` with subfolders), or "…with the default title" when there is no template. Open (Enter) opens that day's note or creates it like Today's Note, with `{{date}}` and `{{title}}` set to the chosen day and `{{time}}` to now; Esc cancels. Unavailable until a folder is open.
- **Previous / Next Daily Note** (Ctrl+Alt+[ / Ctrl+Alt+], main menu under Today's Note): while a daily note (named like the daily note name, `YYYY-MM-DD.md` by default, in the daily notes folder or its subfolders) is open, opens the nearest earlier / later one that exists, skipping gaps; never creates a note. Next is greyed out on the latest; Previous from any other note opens the most recent daily note. Each step goes into Back / Forward like any open.
- **New from Template** (main menu ▸ New from Template): lists the `.md` notes in the templates folder of the open folder (Preferences ▸ Notes ▸ Templates Folder, `Templates` by default, a path relative to the open folder like the daily notes folder), by name without the extension. Picking one creates `Untitled.md` (`Untitled 2.md`, … if taken; never overwrites) in the open note's folder, or the open folder, with the template's text filled in, and opens it with the cursor at the template's `{{cursor}}`, or at the end. Four placeholders, written exactly like this (case matters, no spaces inside the braces): `{{date}}` → today's date (`YYYY-MM-DD`), `{{time}}` → the time now (`HH:MM`, 24-hour), `{{title}}` → the new note's name, `{{cursor}}` → removed, and the cursor starts where the first one was. Both date and time support moment-style formatting, e.g. `{{date:dddd, MMMM D, YYYY}}` → Sunday, November 1, 2026 (`{{time:h:mm A}}` → 9:05 AM, `{{date:[Week] YY}}` → Week 26; `[…]` escapes literal text). When the templates folder is missing or has no `.md` notes, **Create Starter Templates…** below the greyed-out "No Templates" creates the folder with four ready-made templates (Meeting Notes, Project, Book Notes, Weekly Review) that show the placeholders, reveals it in the sidebar and lists them in the menu. Unavailable until a folder is open.
- **New Note from Selection** (Shift+Ctrl+Alt+N, or main menu ▸ New Note from Selection…): moves the selected text into a note of its own and leaves a `[[wiki link]]` to it in its place, to split a long note into linked notes. It asks for the name, suggested from the selection's first line (a heading's text, list, quote and task markers, `**` and backticks left out, up to 60 characters; `Name 2` when `Name.md` is taken). The note goes where New File puts it (the open note's folder inside the open folder; without an open folder, beside the note), with the selection minus its leading and trailing blank lines, and never replaces a file. The link is `[[Name]]`, or `[[Folder/Name]]` when another note has that name, and stands on its own line when whole lines were selected. You stay in the note with the link selected: Ctrl+Z brings the text back (the new note stays), Ctrl+click on the link opens the new note and Back returns. Available with text selected in the editor.
- **Back / Forward** (Alt+Left / Alt+Right, or the main menu): return to the note you came from after following a link, a backlink, Open Quickly or the sidebar, then forward again, like a browser. Each window keeps its own list of the last 50 notes; opening another note after Back drops the notes ahead, and notes deleted since are skipped. A note in another folder opens with its folder.
- **Open Quickly** (Ctrl+P): jump to any file by name; with the box empty it lists the notes you opened last, so Ctrl+P, Enter goes back to the previous note, then your Favorites (starred). Typing finds favourite notes and folders too, ahead of other notes that match as well; a folder is shown in the sidebar. It also finds notes by their front-matter aliases (`aliases:`), matched like names: a row reads “Alias → Note” and opens that note; a note whose own name matches is listed once, and a note actually named like the alias comes first. When no name or alias matches, Enter creates a note with that name. Start the query with `#` to search the headings of every note instead (`#budget`): rows read “Heading — Note”, best matches first as for names, and Enter opens that note at the heading, as a `[[Note#Heading]]` link does. Headings in code blocks and front matter don’t count, and a `#` query never creates a note.
- **Find in Folder** (Shift+Ctrl+F): full-text search across all notes in the folder, fast even with thousands of files. Match Case, Whole Word and Regex toggles under the search box (all off by default, remembered across restarts).
  **Find in one folder**: right-click a folder in the sidebar ▸ Find in “Name”… opens Find in Folder limited to the notes in that folder and its subfolders. A chip under the search box reads "In Folder/Sub"; its ✕ searches the whole folder again. Result paths stay relative to the open folder, and Replace All changes only the listed notes, so it stays inside the folder. Shift+Ctrl+F always starts unscoped; the scope is not remembered.
  **Search operators**: `tag:name` and `path:text` words anywhere in the query (in any case: `TAG:work`) narrow the notes before the text search, so `budget tag:work -path:Archive/` finds "budget" only in notes tagged `#work` outside `Archive/`. `tag:` matches inline and front-matter tags, the tag itself and its nested tags (`tag:work` also finds `#work/urgent`), ignoring case. `path:` matches when the note's path inside the open folder contains the text, ignoring case (`path:Clients/`). Several operators must all hold; a leading `-` excludes (`-tag:done`); quotes allow spaces (`path:"Old Notes/"`). Match Case, Whole Word and Regex apply to the text that is left. Operators without text list each matching note once with its first line; Replace All is off for such a list. A bare `tag:` or `path:` is searched as text.
  **Find Broken Links…** (main menu, or the Broken Links toggle next to Regex): lists every link in the folder's notes that leads nowhere, so links broken by a rename or move outside the app (Files, another computer, Git) can be fixed. A `[[wiki link]]` is broken when no note has that name or alias (the same rule as Ctrl+click), or when its heading part names no heading of that note: `[[Note#Heading]]`, `[[Note#Heading|text]]`, `![[Note#Heading]]` and `[[#Heading]]` (this note) are matched as following the link matches them (by title in any case or by heading id; headings in code blocks and front matter don't count), and the row reads “Note#Heading — no such heading” (a missing note is listed once, as the link); a relative link or image (`[text](Note.md)`, `![](assets/x.png)`, `<path with spaces.md>`, `%20` decoded) when its file does not exist relative to the note. URLs, `mailto:`, absolute paths, `#anchor` links and the `#part` of Markdown links, code and front matter are skipped. The search box becomes a "Broken links" chip (its ✕ returns to text search), each row shows the note, line and link as written and opens the note at that line, and the count reads "N broken links in M notes". Replace All is off in this mode. The list is made when the mode is turned on or chosen from the menu again; it does not update while you edit. A folder scope (Find in “Name”…) applies too.
  **Find Open Tasks…** (main menu, or the Open Tasks toggle next to Broken Links): lists every unchecked task in the folder's notes, so everything still to do is in one list. A task is a list item marked `- [ ]` (also `*`, `+`, `1.` or `1)`), indented or inside a `>` quote too; `- [x]` is done and not listed, and tasks in code blocks and front matter are skipped. The search box becomes an "Open tasks" chip (its ✕ returns to text search; Broken Links and Open Tasks turn each other off), each row shows the note, line and task text and opens the note at that line, where Toggle Task (Ctrl+Enter) checks it off. The count reads "N open tasks in M notes" (the first 500 are listed). Replace All is off in this mode. The list is made when the mode is turned on or chosen from the menu again; it does not update while you edit. A folder scope (Find in “Name”…) applies too.
  **Find Unused Attachments…** (main menu, or the Unused Attachments toggle next to Open Tasks): lists the files in `assets` folders and the configured attachments folder (where pasted and dropped images go, at any depth of the open folder) that no note uses, so you can clean them up after images were removed from the text: every file there except notes, hidden files and symlinks. A file counts as used when a note links to it or shows it with a relative path, as Find Broken Links reads links (`![](assets/x.png)`, `[t](assets/doc.pdf)`, `[t](<assets/my file.png>)`, a `[ref]: assets/x.png` definition; percent-encoded names such as `my%20photo.png` resolve, and names match ignoring case), or with an HTML `<img src="assets/x.png">`; links in code, code spans and front matter don't count, nor do `[[wiki links]]`. The search box becomes an "Unused attachments" chip (its ✕ returns to text search), each row shows the file's path and size, and Enter or a double-click shows it in Files. MarkdownMate never deletes them: check and delete in Files. The count reads "N unused files (size)" (the first 500 are listed); notes that could not be read are named, because files only they use are listed too. A folder scope (Find in “Name”…) lists only the attachments under that folder, still checked against all notes. The list is made when the mode is turned on or chosen from the menu again; it does not update while you edit.
  **Regex** searches with a regular expression in [Rust regex syntax](https://docs.rs/regex/latest/regex/#syntax), for example `\d{4}-\d{2}-\d{2}` or `^- \[ \]`. Match Case off ignores case; Whole Word makes the whole pattern match whole words. Notes are searched line by line, so a match never spans two lines and `^` / `$` are the start and end of a line. An invalid pattern shows why under the search box and lists nothing.
  **Replace All** under the search box replaces every listed match (follows the toggles; without Regex your replacement is inserted exactly as typed; with Regex `$1`…`$9` insert a group (`${1}` when a letter, digit or `_` follows), `${name}` a named group and `$$` a literal `$`) in all result notes, after confirming "Replace N matches in M notes?". Ctrl+Z undoes it in the open note; a note changed on disk after the search is left alone and named. The search then runs again.
- **Other files**: images open in a built-in viewer; anything else opens in its default app.

## And also

- **Main menu** (the menu button at the left of the header bar, or F10): New File / New Folder… / New from Template / New Note from Selection… / Today's Note / Previous and Next Daily Note / Daily Note for Date…, Open File… (a `.md` note opens with its folder) / Open Folder… (Ctrl+O), Open Recent, Back / Forward, Edit (Move Line Up / Down, Duplicate Line, Copy Link to Block), Format (Highlight, Toggle Task, Footnote, Format Bar) and Table (Insert Table and the table commands), Export as PDF… / Export as HTML… / Export Folder as HTML… / Export as Plain Text… / Export as RTF… / Export as Word… / Copy as HTML / Copy as Rich Text / Print…, Keyboard Shortcuts (Ctrl+?), What's New, About MarkdownMate.
- **Export as PDF…** (main menu): the note as Print renders it, saved straight to a PDF (suggested as `<note>.pdf` next to the note) without the print dialog.
- **Export as HTML…** (Shift+Ctrl+E or the main menu): one standalone `.html` file (CSS embedded, light theme, code highlighting, KaTeX formulas, Mermaid diagrams as SVG, no script), suggested as `<note>.html` next to the note. Relative images and links stay relative, so keep the file next to the note (or copy its images along); wiki links become relative links to the target note, unresolved ones plain text.
- **Export Folder as HTML…** (main menu, with a folder open): turns the whole folder into HTML pages you can open in a browser, publish or hand over. Pick an empty folder (or create a new one) as the destination; every note becomes a standalone page like Export as HTML gives, at the same place in the same subfolders, with `.html` instead of `.md`. Wiki links (by alias too) and relative links to other notes (`other.md#heading` too) open the right page, images shown by a relative path inside the folder are copied alongside, and so is every `assets` and configured attachments folder, whole (PDFs, stylesheets and other files too). Images outside the folder, other linked files and symlinks leading out of the folder are not copied. An `index.html` at the top lists every note as a tree by folder, in the sidebar's order. Hidden files and folders, `.git` and `node_modules` are skipped, as in the sidebar. A note named like the index (`index.md` at the top) or two notes with the same name (`a.md` and `a.markdown`) get a number: `index 2.html`. Thousands of notes take a few seconds; a dialog shows the progress and Cancel stops the export, keeping the pages already written, with an `index.html` that lists them. Notes with Mermaid diagrams or formulas are drawn as in Export as HTML afterwards, one at a time. When it is done, a message gives the count and Show in Files opens the destination.
- **Export as RTF…** (main menu): the note as a `.rtf` file (suggested as `<note>.rtf` next to the note) that opens formatted in LibreOffice Writer, AbiWord and other word processors: headings (bold, larger), bold, italic and strikethrough, highlights on yellow, links, bullet, numbered and to-do lists with indentation, quotes indented, alerts as an indented quote under a bold title in their colour, code and inline code in a monospace font, tables with borders, formulas as their TeX, images as `alt (path)` text. Front matter and raw HTML are left out; accents, Vietnamese and emoji are kept.
- **Export as Word…** (main menu): the note as a `.docx` file (suggested as `<note>.docx` next to the note) that opens in LibreOffice Writer and Microsoft Word with the same content as Export as RTF, in real Word styles: headings in Heading 1–6 (so the navigator and a table of contents work), quotes in the Quote style, code in a monospace Code style; bold, italic, strikethrough, highlights on yellow, working links, bullet, numbered and to-do lists (☐ / ☑) nested per level, alerts and callouts under a bold title in their colour, tables with borders and a bold header row, horizontal rules, footnotes as `[1]`, formulas as their TeX. PNG, JPEG and GIF images next to the note (relative paths) or embedded with `![[name]]` in the open folder go inside the file at their size (`|300` sets the width); web images and other formats become their alt text. Front matter and raw HTML are left out.
- **Export as Plain Text…** (main menu): the note without Markdown syntax in a `.txt` file (suggested as `<note>.txt` next to the note): headings as their text, bullets as `• ` (numbered lists keep their numbers, to-dos become `[ ]` / `[x]`), links as `text (url)`, code kept as written, formulas as their TeX between `$` / `$$`, tables as tab-separated rows, quotes with `> `. Front matter and raw HTML are left out.
- **Copy as HTML** (Alt+Shift+Ctrl+C): copies the selection (or the whole note) so it pastes formatted into rich-text apps (mail, Docs) and as Markdown into plain-text apps. No page styling or script; code blocks are plain monospace (no colours), formulas MathML; links as in Export as HTML (wiki links relative, unresolved ones plain text).
- **Copy as Rich Text** (main menu, no shortcut): copies the selection (or the whole note) so it pastes formatted into LibreOffice, Thunderbird and web mail — headings, bold and italic, highlights on yellow, lists, links, tables (with borders), code in monospace, formulas as MathML, diagrams as code — and as plain text (the Export as Plain Text output) into plain-text apps. Images in the open folder go along inside the copy; web images stay links to the web; other images are left out.
- **Print…** (Shift+Ctrl+P or the main menu): the note as the preview renders it (unsaved edits included, always light, no background), from Edit, Preview or Side by side, to a printer or GTK's Print to File (PDF). Code blocks, tables and images are kept off page breaks where they fit.
- **Auto-save** directly to disk, and **Reload** (Ctrl+R) from disk — with unsaved edits it asks first (Reload drops them and clears undo).
- **Session restore**: reopens your folder and note, the cursor position in each note (the last 100 notes; a target line from Find in Folder / Go to Line wins) and the expanded sidebar folders.
- **Preferences** (Ctrl+, or the header-bar button): editor font and size (system monospace by default), line numbers, line wrapping, list indent width (2 / 4 spaces), line spacing, text width, typewriter scrolling, auto-pairing brackets and quotes, spell check, style, theme, sync scrolling, line breaks, smart punctuation, loading images from the web, the format and width of pasted images. Changes apply at once and are remembered. Preferences ▸ Default App shows whether MarkdownMate opens Markdown files (`text/markdown`, `text/x-markdown`) and has a Make Default button that sets it (the same as Files ▸ Open With ▸ Set as default); it needs the installed package, and a failure shows a message at the bottom of the window. Nothing asks at launch.
- **About** (Preferences ▸ About): the app's version (click it to copy), What's New, Send Feedback (opens your mail app with the app version, Ubuntu release and kernel filled in; without a mail app the address is copied), Share MarkdownMate (copies a link to send), Donate, More Apps from HomieLab and the MarkdownMate website, all opened in your browser. **What's New** (also in the main menu and the About dialog) lists the highlights of each feature release; after an update a dot on the main menu button, its What's New item and the Preferences row says there is something new, until you open it once. It never opens on its own, and a fresh install starts with no dot.
- **Light / Dark / System** appearance: Preferences ▸ Appearance ▸ Style (System by default) switches the window, editor and preview at once and is remembered.
- **Zoom** (Ctrl+= or Ctrl++ in, Ctrl+− out, Ctrl+0 back to 100%): editor text and preview, 10% steps from 50% to 300%, remembered. The sidebar and header bar keep their size; Print and Export HTML are not zoomed.
- **Default app** for `.md` files, if you want it.

Not ported (macOS-only): Services menu, Share sheet, Shortcuts/Siri actions, Quick Look, iCloud integration.
